NumPy 2). CI re-runs the tests on Python 3.12 on every push.

full Jacobian is covered. Pass threshold: 1e-6.

## Tokenizer on TinyStories

Commands: `make tokenizer` and `make bench`. Trained on the first 5 MB of `TinyStories-valid.txt`
and measured on the next 5 MB, which the tokenizer never saw.

| Vocab size | Merges | Training time | Held-out tokens | Bytes per token | Round trip | Encode speed |
|---|---|---|---|---|---|---|
| 512 | 255 | 0.6 s | 2,116,606 | 2.36 | lossless | 9.3 MB/s |
| 1024 | 767 | 1.3 s | 1,607,775 | 3.11 | lossless | 10.1 MB/s |
| 4096 | 3,839 | 4.6 s | 1,249,262 | 4.00 | lossless | 9.7 MB/s |

### Reading the numbers

- Raw bytes would need 5,000,000 tokens. The 1024 vocabulary cuts that by 3.1x, so the model sees
  3.1 times more story per attention window.
- Going from 1024 to 4096 tokens needs 22% fewer tokens but quadruples the embedding and
  output layers. M2 starts with 1024 as the trade-off for a small model.
- The trained tokenizers are committed in `artifacts/` so anyone can check these numbers.

## Recheck (2026-10-06)

Same machine (Intel Core i7-13700H, Windows 11). Every suite, lint and dependency audit was run again:

- ruff: clean. `pytest`: 61 passed (5 new download tests). `pip-audit`: no known vulnerabilities.
- The download now comes from a fixed dataset commit (`f54c09f`) and is checked against the size
  and SHA-256 that Hugging Face publishes; a tampered, oversized or changed file is refused and
  removed, and an existing copy is checked rather than trusted.
- `make bench` on the verified file: 2,116,606 / 1,607,775 / 1,249,262 held-out tokens for
  vocab 512 / 1024 / 4096, identical to the table above.
