# Quality check, 2026-11-01

The owner's 10 rules, checked against the code on Windows 11 with Python 3.14.5 and NumPy 2.5.4.
No model is trained in M1, so there is no GPU run and no model file to delete.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | The only network call, `data._fetch`, has a 60 s timeout, refuses more bytes than published and checks size and SHA-256; a failed download deletes its `.part` file and re-raises (`except BaseException: ... raise`). No retries, so no backoff is needed: a re-run starts the download again. No swallowed errors. |
| 2 | Writes safe to retry | fixed | The download writes `.part` and renames it into place; a verified copy is reused. `BPETokenizer.save` wrote the JSON in place, so an interrupted save left a truncated tokenizer that `load` would fail on: it now writes `<name>.tmp` and renames it (`test_save_leaves_no_temporary_file`, and a mutant that leaves the `.tmp` behind is killed). Training is deterministic, so a re-run writes the same file. |
| 3 | No race conditions | fixed | `no_grad()` switched a module-wide flag, so inference in one thread under `no_grad()` silently stopped graph recording for training in another. The flag is now per thread (`threading.local`), as PyTorch's grad mode is; `test_no_grad_in_one_thread_does_not_stop_another_threads_graph`. Tensors themselves are not thread-safe to share, like NumPy arrays. |
| 4 | Don't trust the clock | pass | Timings in the CLI use `time.perf_counter()`. No stored timestamps. |
| 5 | Read before changing | pass | No environment variables. `threading.local` and `argparse.ArgumentTypeError` are standard library. Paths in the README (`artifacts/`, `data/`) exist or are created by `make data`. |
| 6 | Never break compatibility | pass | The tokenizer file format (`version: 1`) is unchanged and all three committed tokenizers (512, 1024, 4096) load and round-trip under the new checks. `no_grad()` behaves the same in single-threaded code. |
| 7 | One source of truth | pass | The encode cache (`_cache`) is derived from the merges, which never change after construction, and is capped at 100,000 entries. Dataset revision, size and SHA-256 live only in `data.FILES`. |
| 8 | Small changes, no secrets, validate input | fixed | No secrets. `BPETokenizer.load` turned a malformed merges list into a `KeyError` or `TypeError` deep in the constructor: it now refuses any merge that is not two earlier token ids with `merge i must be two ids of earlier tokens`. The CLI accepted `--max-bytes -1` (which reads the whole file), `--max-bytes 0`, negative `--skip-bytes` and a vocab under 257, and `stats` on empty input crashed with `ZeroDivisionError`: all now exit 2 with a clear message. No new dependency. |
| 9 | Tests that can actually fail | fixed | No skips or tautologies. Mutation check below. |
| 10 | Re-verify | pass | `ruff check .`: All checks passed; `ruff format --check .`: 17 files already formatted; `pytest -q`: 85 passed; `pip-audit --skip-editable`: No known vulnerabilities found; `audit_repo.py tiny-transformer-scratch`: OK. CI result in `docs/results/m1.md`. |
